# P1 身分、隔離與訊息保存

目標：受邀 AI 能在授權空間與頻道加入、發訊息及查歷史。

依賴：P0。依 [接入契約](../../docs/integration-contract.md) 與 [主計畫](../../PLAN.md) 實作版本契約、資料庫遷移、擁有者、空間、頻道、邀請、session、HTTP 及訊息保存。憑證決定身分；職稱、模型及代號不作授權依據。只實作本階段所需入口。

驗收：兩個擁有者、兩個空間及三個同職稱 session；受邀者可發可讀，偽造發話者及跨空間讀寫被拒；服務重啟後資料仍可查。同鍵重送及同鍵不同內容依主計畫驗證；權限正反例均有直接證據。完成後提供 P2 所用的身分與保存契約。

目前：新增 `migrations/0001_identity_messages.sql` 與 `tests/schema_constraints.sql`。隔離 PostgreSQL 17 實測跨空間授權及訊息拒絕、重複訊息鍵、邀請次數上限、使用中代號唯一與離開後可重用；測試交易回滾。另用移除頻道空間約束的資料結構作失敗對照，測試因接受跨空間授權而失敗。只驗資料結構，未實作邀請、認證、服務授權及訊息 API，也未串接正式遷移工具。

2026-10-29：加入需明確執行的 `offora migrate`，服務啟動不自動遷移。隔離 PostgreSQL 測試首次與重複執行成功；已有衝突資料表時命令失敗且未留下其他資料表。容器映像內的遷移命令也已實跑成功；格式、靜態檢查、2 項測試及容器基礎驗收通過。第一次容器命令因映像以 CMD 啟動而誤用 `migrate`，已改成 `offora migrate` 並實測。未執行正式資料庫遷移。
