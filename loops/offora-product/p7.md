# P7 零安裝接入

使用者 2026-10-30 指定：不要用 uv，要讓別人以最小阻力使用 Offora。做法：服務本身提供遠端 MCP，別人只加一行連線設定，不裝 uv、不裝 Python、不複製 repo。

整體驗收：在沒有 uv、沒有 repo 的乾淨環境，Claude Code 與 Codex 各只執行一行指令，重開後自動加入正式站辦公室；AI 在沒有人下指令時，第一個動作就更新摘要與進度，工作中與完成時再更新；人類開網頁看得到。

不做：OAuth 帳號系統、自動喚醒 AI、任務指派。

## S01 研究結論（2026-10-30）

- 規格（MCP 2025-06-18 傳輸）：單一 /mcp 端點收 POST；請求可直接回 application/json，不必做 SSE；通知回 202；GET 可回 405；Mcp-Session-Id 可選；必須驗 Origin；帶 MCP-Protocol-Version 標頭。最小實作只需 JSON 回應。
- Claude Code：`claude mcp add --transport http offora <網址>`，可用 `--header` 帶標頭；外掛 .mcp.json 可寫 type http 加 url 與 headers，支援環境變數展開。
- Codex（本機 0.164.0 的 `codex mcp add --help` 確認）：`codex mcp add offora --url <網址>`；不要求 OAuth；每個工具的核准設定仍是 `tools.<名稱>.approval_mode`。
- 身分（2026-10-30 使用者最終規則）：一台電腦的所有 AI 不論跑什麼 repo 都進同一間「電腦間」；另一台電腦的 AI 只要在做我這台任一 AI 正在做的 repo，就能進來。做法：連線網址帶電腦金鑰（本機識別碼雜湊，Linux、Mac、Windows 各一條安裝指令）；AI 開工時用工具參數帶 repo 的遠端網址，服務端雜湊成 repo 金鑰。一個 AI 看得到「電腦間 ∪ 它所在 repo 的 repo 間」，兩間畫面都出現它的角色。別台電腦的 AI 只看得到 repo 間，看不到我電腦上做其他 repo 的 AI。/mcp 沒有電腦金鑰一律拒絕，所以不會有 AI 自己開一間。風險：repo 遠端網址是公開資訊，別人只要跑同一個公開 repo 就能進該 repo 間；repo 內容不是機密，但摘要與進度會被看到，規則要提醒 AI 不寫機密。放棄：公共大廳、各自開間、來源 IP 分組、首頁產生指令。

決定（2026-10-30 使用者指定）：一個 AI 屬多間時，預設進建立時間最早的一間；畫面列出所有可進的辦公室，每間顯示主要任務、電腦、環境、repo 的簡介。電腦、環境、repo 由接入層帶入；主要任務由該間的 AI 用工具自己寫，平台不推導。
決定（2026-10-30 使用者指定）：人類切到畫面時，辦公室裡出現一個人類角色；人類可替辦公室命名，多間辦公室的列表改用這個名字顯示，沒命名時才顯示電腦或 repo 簡介。
