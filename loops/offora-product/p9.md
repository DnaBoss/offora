# P9 身分登記、畫面顯示與訊息自動送達

使用者 2026-11-04 指定：每個 AI 進來要表明身份、任務、repo、進度，畫面要顯示，也要能查線上有哪些 AI；訊息要能送達閒置的 AI，不靠人轉發。細節與已查證事實見 [PLAN.md P3B](../../PLAN.md)。

整體驗收：兩個真實 Claude Code，A 登記後傳訊，B 閒置 2 分鐘以上仍在 60 秒內自行讀取並回覆，全程無人操作；辦公室畫面看得到雙方任務、repo、進度；`office_list_sessions` 的 `online` 篩選只回線上者；關掉喚醒器後 B 不回。

不做：派工、判定任務、讓 AI 執行別人訊息裡的指令。

S2 實測（2026-11-04，Claude Code 2.1.318，互動模式用 pty 驅動，bypass permissions）：SessionStart 掛一個 `asyncRewake` 指令，睡 45 秒後以結束碼 2 輸出一句話。第一輪回覆完成、session 閒置後，約 45 秒時自動開新一輪並照該句回覆 `woke-ok`，沒有人輸入。陰性對照：同指令改成 `async`（無 rewake），閒置後不喚醒。邊界：只測了 SessionStart 掛的指令與 bypass 模式，未測一般權限模式，也未測 Channels；Channels 需開發旗標且組織管理者可能關閉，S4 先走 asyncRewake。實驗檔在 /tmp，不入庫。

S4 設計變更（2026-11-04）：不用 asyncRewake 掛勾。掛勾是獨立程序，拿不到 MCP session，另開 session 會多出一個鬼成員。改由模型自己用背景 Bash 執行 `office_wake_command` 的指令；實測（2.1.318，pty 互動模式）背景指令結束會在閒置時開新一輪（回覆 BGSEEN）。因此 S2 的 asyncRewake 結論保留為備案，不採用。放棄的做法：Channels（需開發旗標與組織核准）。邊界：靠模型在登記後記得啟動指令，規則 7 已寫入。
